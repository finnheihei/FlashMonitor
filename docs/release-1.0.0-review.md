# Monitor 1.0.0 发布审查与产品方向

审查日期：2026-10-20。基于当前工作区 0.9.12 源码及已有未提交改动。

**结论：先完成发布候选版收口，再发布 1.0.0。核心监控能力已具备，但数据归属、网站边界和实际界面验收仍有未关闭项。**

本轮完成代码审查、故障复现、五类问题修复及回归。没有升级正在运行的实例、修改日常 Clash 配置、打发布标签或发布新版本。保留了工作区原有改动。

## 1. 产品核心竞争力

建议定位：**面向 Windows Clash / mihomo 用户的代理流量账本。看清哪个应用访问哪个网站、实际走什么线路、消耗多少代理流量。**

用户打开产品后，应能迅速回答：

1. 这个应用或网站现在走代理、直连，还是两者混合？
2. 今天是谁用了最多代理流量？其中哪些目标域名占大头？
3. 这个判断来自哪条连接、哪个节点、哪条规则？哪些流量没有观察到？

竞争参照：MetaCubeXD 官方仓库已经列出实时流量统计和连接管理；zashboard 的历史连接组件已经支持按目标、进程等维度聚合。因此“能看连接”“有流量排行”“有历史记录”本身不足以形成明显区分。

- [MetaCubeXD 官方仓库](https://github.com/MetaCubeX/metacubexd)
- [zashboard 历史连接组件](https://github.com/Zephyruso/zashboard/blob/main/src/components/overview/ConnectionHistory.vue)

更有潜力的组合优势是：Windows 应用身份识别、本地持续保存、代理与直连独立计量、应用和网站交叉追溯、清楚标出未知和采样缺口，以及两步内找到流量大户。这里是产品方向判断，尚未通过用户测试证明市场优势。

必须准确界定产品承诺：目标域名不等于浏览器标签页；CDN 和第三方资源可能属于同一页面。采样到的核心连接流量不等于全机网卡流量，也不等于机场最终计费流量。无法归因的部分应保留为未知，不填成零或直连。

## 2. 本轮已经修复的问题

| 编号 | 严重度 | 问题与后果 | 修复与证据 |
| --- | --- | --- | --- |
| F1 | P1 | 网站先按总流量取前 80 名，再按代理筛选。100 个大直连网站足以挤掉代理流量第一名。应用内前 12 网站和累计摘要也有同类问题。 | `store._traffic_leaders` 分别保留总量、代理、直连的领先项并取并集；全局最多 240 项，应用展示最多 36 项，累计内存摘要最多 120 项。覆盖榜首保留、去重、边界及落盘重启回归。 |
| F2 | P1 | `ClashClient.payload` 将缺少 connections 的错误对象当成连接清空。恢复时同一个连接可能再次计入全部字节。 | 缺少字段的响应不再作为有效快照。显式空列表和 null 保持兼容；“100 B → 错误响应 → 120 B”的累计为 120 B，而不是 220 B。 |
| F3 | P1 | `chains` 中的 null、数字、布尔值被转成字符串，再被认作代理节点。 | 非字符串路由链返回未知；不把父策略组提升成最终出站。 |
| F4 | P2 | IPv6 地址直接拼接端口，网站统计把端口也当成地址的一部分。 | IPv6 远端写为 `[2001:db8::1]:443`，网站键正确提取 `2001:db8::1`。 |
| F5 | P2 | 页面 CSV 做了公式前缀处理，后端 CSV 导出入口没有同等保护。 | 后端转义 `= + - @` 及制表/换行开头的文本单元格，数值仍保持字节数；页面也补齐换行前缀。 |

同时将网站摘要文案改为明确说明：分别保留不同流量口径的主要网站，搜索仅限摘要。修复没有恢复旧版已经裁掉的网站历史，也没有将摘要升级为全量查询。

修改文件：`flashmonitor/clash.py`、`flashmonitor/classify.py`、`flashmonitor/collector.py`、`flashmonitor/store.py`、`ui.html`；新增 `tests/test_release_readiness.py`。

## 3. 发布前还需要关闭的问题

P1 表示会直接伤害核心判断或发布可靠性；P2 表示体验、功能深度或后续维护问题。

| 编号 | 优先级 | 状态及证据 | 处理要求 |
| --- | --- | --- | --- |
| R1 | P1 | **已复现，未修复：切换控制器仍优先读取旧地址。** `ClashClient.base_urls` 优先 `_base_ok`；`AppContext._after_settings_saved` 没有重置控制器状态。配置从 9090 改到 9097，返回首选地址仍为 9090。 | 显式地址变更后废弃旧连接/配置缓存；采样、流量流、手动刷新统一绑定同一来源和代次。展示实际接入源。双控制器测试覆盖切换中旧响应迟到。仅清一个缓存不足以解决并发流来源混用。 |
| R2 | P1 | **已复现，未修复：不同托管站点合并。** `site_key('alice.github.io')` 与 `site_key('bob.github.io')` 都为 `github.io`；`one.vercel.app` 和 `two.vercel.app` 同样合并。 | 使用包含私有后缀规则的可维护域名归并策略，或保守保留精确主机名。统计分组和执行域名范围必须分离，不能自动把聚合结果当成可操作的公共父域名。旧统计不可静默声称已重新归因。 |
| R3 | P1 | **代码确认，未修复：默认忽略全部 WebView2 进程。** 新配置的 `DEFAULT_IGNORE` 含 `msedgewebview2`；首页和实时用量过滤忽略名单。其他 WebView 应用可能因此不出现。 | 自身进程排除应依据本应用的进程归属；不能默认按共享宿主名称排除所有应用。展示隐藏项数量和快速恢复入口。已有用户自定义忽略项要保留选择权。 |
| R4 | P1 | **发布门禁缺口：实际 HTTP、安全路由、原生网络和更新替换未通过本环境验收。** 详情见测试结果。 | 在普通 Windows 权限环境复验完整套件，以及最终 exe 的首次安装、升级、关闭到托盘和退出写盘。未通过前不能把候选版标为完成。 |
| R5 | P1 | **分发校验不一致。** `install.ps1` 只检查下载大小；在线更新在缺少 digest 时也允许仅按大小继续。README 的 SHA256 承诺不覆盖全部路径。 | 发布产物提供校验清单；安装与更新统一要求可信来源及摘要，失败时保留旧版本。数字签名可单列交付计划；不能把关闭安全保护当成正常安装路径。 |
| R6 | P2 | **网站维度缺少完整闭环。** 首页以应用为中心；展开只列当前连接数最多的 8 个目标。累计网站是摘要，全局网站项不能直接反查访问它的应用。 | 增加网站实时视图；实现“应用 → 网站”和“网站 → 应用”的同时间范围下钻。全量搜索/分页独立于首页 Top N 摘要。 |
| R7 | P2 | **历史应用身份仍按进程名合计。** 实时可展示多个路径，累计 `programs` 仍以名称为键。不同路径的同名程序难以分别追账。 | 以可信路径或稳定应用身份记录新增历史，名称合计保留为显式分组。路径缺失和旧记录标明归因能力，避免伪造迁移结果。 |
| R8 | P2 | **“代理预算”场景缺失。** `quota_alerts` 使用全部上传下载，直连大下载也会触发总量提醒。 | 提供独立代理预算口径，并在通知中注明期间、口径、应用/网站和已用量。保留原总量提醒含义，不能静默改旧设置。 |
| R9 | P2 | **时间与完整性解释不足。** 统计按 15 分钟桶聚合；程序累计、保留期内的网站/节点、7 天应用网站明细覆盖不同；短于采样间隔的连接可能漏记。 | 用简短统计说明明确起点、保留范围、时间粒度及未归因量。避免将程序累计和网站累计在不同覆盖范围下直接相减。 |
| R10 | P2 | **控制器写操作会尝试其他候选地址。** `close_connection` 在失败后遍历 `base_urls`；当前页面没有把来源标识随连接 ID 一起提交。 | 断开操作只发往展示该连接的控制器；来源已改变时拒绝并要求刷新。用两个假控制器、重复 ID 和首个请求失败来测试，不能依赖随机 ID 通常不冲突。 |

R1、R2、R3 均有直接代码或可执行复现依据；其余分别为代码发现或未完成的发布验证。没有把“尚未验收”计作已经确认的用户故障。

## 4. 使用流程与简约风格

**证据限制：本轮浏览器在附加标签时持续断开，未得到可接受的当前页面截图。以下为 HTML/CSS 和交互代码审查，不是实际视觉验收，也不构成可访问性合规结论。** 没有使用旧截图替代新证据。

| 步骤 | 用户任务 | 当前健康度与依据 | 建议 |
| --- | --- | --- | --- |
| 1 | 首次连接 Clash | 中：已有接入引导、测试和错误反馈；接入源选择存在 R1。 | 顶部显示实际控制器及最后成功采样时间，错误信息与恢复动作放在一起。 |
| 2 | 查看应用的实际路由 | 中：代理、直连、混合、未知、拒绝已有文字状态；默认隐藏项和多身份合计仍会影响理解。 | 固定列为应用、实际路由、下载、上传；路径与身份细节展开后显示。混合必须保持可见。 |
| 3 | 找今天的代理流量大户 | 弱：入口为“累计”，点击后切到 all/program/all；网站、时间和流量口径位于可折叠筛选。 | 主导航改为“实时 / 用量”；用量默认今天、代理降序。“应用 / 网站”和时间范围常驻，搜索与高级筛选可折叠。 |
| 4 | 确认应用访问哪些网站 | 中：已有当前目标和按应用的网站明细；当前目标按连接数选取，历史存在摘要上限。 | 下钻保留期间和流量口径。提供“查看全部”，明确连接累计字节与当前速率的区别。 |
| 5 | 从网站追到应用 | 弱：缺少反向交叉查询。 | 点击网站直接列出贡献应用、代理字节、占比、当前路由证据。 |
| 6 | 处理异常、退出和升级 | 待实测：已有错误提示、持久化健康状态、退出保存保护；本环境未完成原生链路。 | 发布候选版逐项录制或截图验收，区分“接口未连接”“统计写盘失败”“确实没有流量”。 |

已有可保留的设计基础：浅色中性背景、统一圆角、代理/直连语义色、数字等宽排版、键盘焦点样式、部分无障碍标签，以及默认列表视图。无需从零换一套视觉语言。

简约风需要解决的是主次顺序：

- **让重要答案常驻。** 首页简短显示当前代理速率、今日已观察代理用量和活跃代理应用数。首屏不要用“总速率”代替用户最关心的代理消耗。
- **把高级功能放到后面。** 路径、PID、规则、IPv6 和诊断进入详情或设置；主列表以读数据为中心。入口若只控制 IPv6，应采用更明确的名称。
- **减少小号浅字。** 当前正文 13px，多处辅助内容为 11–12px。`--faint: #9aa2ad` 在白底上的计算对比度约 2.58:1，在页面底色上约 2.36:1。重要计数和身份信息不宜依赖这一档颜色。
- **保留足够的文字对比与行高。** 建议主内容 14px、表头 12–13px、主要行高约 44px，数字右对齐。以 960×640、1280×800 和 200% 缩放实际验证，不能只凭 CSS 值判断效果。
- **颜色只解释状态。** 蓝色代理、低饱和绿色直连、灰色未知、红色确认异常；同时保留文字。路径、动作、标签不要全部争夺强调色。
- **减少重复解释。** 保留一句可见的统计边界，详细口径放到“统计说明”。当前程序网站明细会重复拼接 coverage、sites_note 和通用提示。

建议的 1.0 信息结构：

| 页面 | 常驻内容 | 展开后内容 |
| --- | --- | --- |
| 实时 | 应用/网站切换；全部/代理/直连/未知；路由与速率列表 | 节点、规则、目标、身份路径及连接详情 |
| 用量 | 今天/7天/30天；应用/网站；代理用量、占比及排行 | 应用与网站交叉明细、下载/上传、完整统计口径 |
| 设置 | 接入源、保存范围、提醒、关于 | IPv6、规则草稿、诊断及其他高级操作 |

以上是待实现方案；本轮没有将未经过截图验证的布局重构合入页面。

## 6. 1.0.0 放行标准

1. 关闭 R1、R2、R3 和 R10；错误控制器、错误网站边界与默认隐藏宿主不能进入正式版的核心路径。
2. 完成安装/更新摘要校验，并在普通 Windows 环境跑通完整套件与最终打包程序的安装、升级、托盘、退出写盘。
3. 让“今天谁用了代理流量”成为直接入口；用户无需理解节点、TUN 或高级筛选即可找到应用和目标域名。
4. 对未知、混合、断线、空数据、隐藏项、历史保留和摘要截断提供准确的可见解释。
5. 完成真实页面截图、键盘操作、小窗口、200% 缩放及长域名/路径验收。用 3–5 位目标用户验证能否在约 10 秒内找到当前代理应用，并在两次下钻内定位主要目标域名；这些是建议目标，不是已有测试成绩。
6. 审阅当前全部未提交源码，确认发布标签包含模块、测试和打包资源。通过上述门禁后再统一版本号并生成 1.0.0 发布产物。

1.1 可以继续做网站→应用历史反查、完整分页历史、按稳定应用身份统计、代理预算与异常增量提醒。1.0 若保留其中的限制，需要在产品承诺与页面中明确说明。
