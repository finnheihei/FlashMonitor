# 一键屏蔽所选范围 IPv6（0.9.12）

从应用或网站打开「连接设置」，窗口直接显示当前对象与「屏蔽 IPv6」开关，打开即生效、关闭即恢复。通用入口可选择应用或输入域名。不会恢复旧诊断草稿，不需要诊断或保存步骤；路径缺失、选择为空或核心不可用时会明确显示原因和重试。已有的其他限制可从「已设置」逐项关闭，其他配置中的限制不会被接管。规则草稿与旧原生 IPv6 方案移至「设置 → 数据」，用户原文件保留。

成功状态为“已开启”，表示所选规则在实际核心中位于原规则之前、原规则顺序完整保留，公开运行设置和手动选择的代理节点已核对。等待核实时会保留开关的已保存意图并明确显示“等待核实”，不显示已开启。只限制核心已识别的 IPv6 目标新连接，IPv4 沿用原路线。不保证应用自动重试 IPv4，也不控制代理远端解析的出口地址族；fake-ip、不可见域名、未识别进程和绕过核心的流量有边界。已有连接不会被主动断开。

设置保存在 Monitor 数据目录 `scoped-ipv6.json`。每 5 秒检查一次；正常状态不会反复写盘或重载。客户端重载后，只有当前配置身份仍匹配、生成文件与运行规则一致时才重新加载限制。重载与恢复会全量加载核心，可能短暂影响网络；客户端重载与维护检查之间不是连续无间隙的屏蔽。退出 Monitor 后不再维护，已加载规则保留到客户端重载；重开 Monitor 可按同一配置身份恢复维护。关闭到托盘继续维护。

此路径使用 [mihomo 的配置加载接口](https://wiki.metacubex.one/api/)，不修改 FlClash 数据库、订阅源、生成配置、全局 IPv6 / DNS 开关或网卡。它不是原生持久附加规则，旧的“继续在 FlClash 设置”流程保持独立。严格强制 IPv4 没有上线，不以本功能冒充。

重载前会只读比较当前配置的 DNS 来源（订阅源或已保存的 DNS 覆写）与生成文件。不同步或无法可靠解析时停止操作，不把旧文件中的 DNS 重新载入。候选配置只能改变本工具的规则，DNS、Hosts、代理定义等全部非规则内容均有指纹核对；写入操作日志后会再次核对，执行和节点恢复后也要检查配置是否变化。撤销与自动维护共用这些保护，并始终基于最新配置。

核心公开接口不提供完整的当前 DNS 配置导出，因此上述保护以 FlClash 已保存并应用的配置为来源；通过其他程序仅临时修改核心、未同步到 FlClash 的 DNS 状态不在可核实范围内。应先在 FlClash 保存并应用 DNS 修复。保护不会把单次 DNS 返回相同 IP 当作配置一致的证明。

当前支持可核实 schema 3 的 FlClash 配置、本机 IP 控制器和 rule 模式的 Meta 核心；应用范围需要 strict / always 进程识别。未知组合规则、外部临时禁用规则、生成文件与公开运行设置不一致等条件会拒绝重载，并保留现状。控制器切换 / profile 切换不会扩大旧限制。生成文件的解析故意保守，遇到未知 YAML 格式需先在客户端重新应用配置。

执行前复查配置身份、文件内容、运行规则与代理组选择，并先持久保存操作日志。核心拒绝时保持原规则；响应丢失时核实当前核心而不重复写入。结果暂不可判断时显示“上次结果待核实”，点击“重新核实”按原日志恢复核对；遇到外部修改则停止覆盖。撤销基于当前客户端生成文件和剩余限制重新合成，不回写旧全量快照，也不按相同文本删除他人的规则。

验证：单元测试覆盖幂等、A/B 独立撤销、重启恢复、订阅规则变化、配置 / 控制器隔离、错误及写盘故障、HTTP 认证和跨站拒绝。`tools/check_scoped_ipv6_core.py` 使用独立 FlClashCore 和本机模拟连接验证真实阻断 / 恢复、组合范围、原 IPv4 DIRECT / PROXY 路线和非默认代理组选择，覆盖 JSON 与 YAML。该测试未修改日常客户端、TUN、DNS 或系统代理，也不等同于真实 TUN 全场景验收。`tools/check_scoped_ipv6_ui.py` 在 Edge 中隔离验证一键操作、重开、失败提示及紧凑布局。
